Here’s one change from start to finish, using the rocket launch as our example. Steps one and two belong to the team: everyone pitches an idea, we vote on one, and we turn it into a prompt, which is just instructions in plain words. A good prompt asks for one change, says to leave everything else alone, and names the tool to use, GSAP. (The full wording is Prompt D in the runbook.) Steps three and four: I paste the prompt into T3 Code and hit send. The agent reads our files, then answers with a plan. Read the plan out loud. In Supervised mode, anything that changes the computer waits for a yes. Steps five and six are the most important: someone reads the request out loud, “It wants to install GSAP. Should we let it?”, and the team votes. Not what we asked for? We press Deny and say why. The agent never approves itself. Once we say yes, npm downloads GSAP and adds it to package.json, the app’s parts list. Steps seven and eight: the agent changes one file and tells us what it did, and we can read every line. Vite reloads the page by itself, we press Launch! together, and if the rocket flies, we make a save point, a git commit. If not, we say what we saw and go back to step two. Quick checks: Why just one change? (Easy to check, easy to undo.) Who presses Approve? (Us, every time.) What’s our next change?
